# How Understory is built

A one-page map for changing the engine: what lives where, the order of a month, where state is kept, and how to add an act, a situation or a system. STATUS.md says what the model does and why; this file says where to find it.

## What is where

**The engine (`src/`)**: everything a world needs, and nothing that only measures it.

**The scale harness (`scale/`)**: identity, speed, city, independence, promotion and twin tests for a city, and the odds fit (`docs/scale/README.md`).

**Tools (`src/tools/`)**: tests and measures. `board.ts` with `predict.ts` and `measure.ts` (the scoreboard); `story.ts`, `personas.ts`, `friends.ts`, `lovetest.ts`, `consequences.ts`, `audit.ts` (what lives are like, with and without a switch); `invariants.ts`, `replay.ts`, `twoworlds.ts`, `demography.ts`, `grouptest.ts`, `test.ts` (`npm test`); `read.ts` (five lives, printed); `coherence.ts` (the twelve fault types over the record and the page, in `npm test`); `props.ts` (the invariants as properties over many seeds). `src/page.ts` holds the page's own rules, shared by the app, `read.ts` and the counter. `src/tools/diag/` holds one-off diagnostics and the two checks for changes that should not alter behaviour: `ident.ts` and `sig.ts`.

**Running**: `./run.sh <script> <args>` runs any script from a pre-built bundle (about a quarter faster than `tsx`, same code). Outputs go to `reports/` and `out-*/`.

## A month

`tick` in `life.ts` runs the systems in this order. Each one draws from its own random stream (`use(w, system)`), so switching one off reshuffles no other system's dice. Every stream is drawn afresh at the start of each month (from the world or run seed, the month and the system), and the draw that decides a choice comes from the chooser's own stream (`chanceOf` in `considerations.ts`), so whatever shifts a stream shifts it only until the month ends, and one person's choices never move another's. The order matters: a system sees what earlier systems did this month.

1. **body**: health, illness; then deaths.
2. **work**: hiring, dismissal, promotion, retirement.
3. **social**: contact through every channel, liking and familiarity, friendships made and lost, gossip.
4. **situations**: answers queued last month first, then the harbour day, then every situation type matched; one situation per person, the weightiest first. Then the spotlight.
5. **threads**, **time** (pursuits, habits, everyday life, attachment), **groups**, **drama**, **projects**, **persona**, **love** (couples' tension, rows, care, doubts, leaving), **romance** (dating, marrying, dating couples parting), **family** (births).
6. **stress**, **money** (with skills and wants), **migration** (leaving and coming home), **yearly** (every twelfth month), then the witness's scores.

A world is built by `buildWorld` (founders, families, jobs at year zero) and then thirty years of the same `tick`; the witness arrives at the present, and the present runs on the same rules.

## Where state lives

- **World** (`world.ts`): `people` and `byId`; `bonds` (one per ordered pair, key `a × 100000 + b`, `a × 2²⁶ + b` in a city, read back with `bkA` and `bkB`: familiarity, liking, trust, respect, memories); `beliefs` (per holder, key `subject|key`, a Gaussian estimate per facet, state, skill or bond); `events` (the record, always in time order, each with its reasons, evidence and who knows it); `queue` (situations for next month); `groups`, `places`, `streams`.
- **Person**: facets (with pseudo-facets: `love:*` for ways of loving, `attach:home`), values, aptitudes, skills, wants, habits, marks, the self-story, if-then signatures, exceptions toward one person, emotions and stress.
- **Couple state** (`love.ts`, `coupleOf`): one object per couple, kept on the partner with the lower id.
- **The `tried` store** (`p.tried[key] = { t, ok, n }`): when something was last tried and how it went. It is also used as a general flag store, with keys made of text (`misread:12`, `stay:40`, `noticed:7:sincerity`). Known debt, below.

## How to add things

**An act**: one `E({...})` in `families.ts`: its family, intensity, the facets that favour it, its words, what it reveals (evidence) and what it does to the bond. Its flags say where it can appear: `named` (only where a situation lists it in `only`), `needsTarget` (needs someone to be done to), `solo`, `quiet`, `secret`, `onlyIf` (only for some people). If it has effects beyond the bond, they go in `run`'s effects in `grammar.ts`. Give it a label in `tools/consequences.ts` (`system`) so the consequence map files it.

**A situation**: a file in `src/situations/`, listed in `TYPES` in `situations/index.ts`, with `match(w)` returning instances: who acts, toward whom, the features, the families and acts allowed, the reason it arose (`cause`, an event, wherever there is one), and its own considerations (`familyExtra` per family). A circumstance that should push one way belongs in the family it pushes toward. A situation that rests on recent history reads it with `recentEvents(w, since)`, never by filtering the whole record. It picks the people who could take part from their settings (`around`, `staffOf`, `near`), never by scanning the whole town (`docs/scale/contract.md`).

**A system**: a tick function called from `tick` at the right point, a name in `SYSTEMS` (its own random stream), an `OFF` switch so its contribution can be measured by switching it off, and a measure in `src/tools/`.

## Switches

`OFF.has(name)` turns a mechanism off, so its contribution can be measured (`OFF=<name>`). `ON.has(name)` is the reverse, for a mechanism that stays in the code off by default (`ON=<name>` turns it on for a test). Every experiment's mechanism gets one. `OFF=fit` turns off the rules that keep lines true and plain (round 41: spans and counts in words, a folded repeat saying which time it was, a friendship's end saying what changed, lines true of the person when said). `OFF=bear` shows every reason a decision gives (round 42: a trait is shown only where the act chosen reads it, a told account only where it decided the choice; page only, behaviour identical). Four mechanisms are on together unless `OFF=together`: occasions, telling, aftermath, and contests out of season and for a place in a band (`collide`, in `drama.ts` and `group.ts`); with them off, each can be turned on alone (`ON=occasions`, `ON=telling`, `ON=aftermath`, `ON=collide`). Read a switch where it is used, never in a value set when a module loads: tools turn switches on after the engine has loaded, so a switch read at load time never takes effect. `CLAUDE.md` says when each kind is removed; the tag of the round that settled it keeps the old behaviour reproducible.

## Checks

- `npm test`: types, the page bundle, the study page, determinism, two worlds at once, groups, invariants (with the consistency audit), demography, the property suite on five seeds, and the coherence counter. The batch report (`npm run batch`) is a report, not a test, and runs separately. The invariants include that every thread event stays on its people's own lists: an act that is not kept comes off them through `unlist` in `grammar.ts`, never by taking the last entry.
- `src/tools/whatif.ts`: what one choice changes in the chooser's life three years on. It copies the world at the start of the decision's month (`src/tools/clone.ts`; `check` proves a copy runs exactly as the original) and runs it with the likeliest other answer and with the same answer, both after the same smallest nudge to chance. The model reads none of it (`globalThis.WHATIF`, in `choose`).
- `src/tools/diag/ident.ts`: for a change that should not alter behaviour. It hashes every event with its words and reasons, every person, bond, memory and belief, and everything else the world carries (groups, plans, rivalries, every random stream, and any record a system keeps on the world, named in the interface or not), on seeds 11–13 and each switch in `IDENT_ARMS` on seed 11; only the lookup tables built from hashed fields are left out (`src/tools/diag/signature.ts`; `src/tools/sigtest.ts` in `npm test` guards both). `save` writes the hashes; `check` compares. CI runs it on every pull request against `main` as it is (`scripts/identity-ci.sh`), hashing both trees with the pull request's own checker, so no stored baseline can go stale and a change to the checker is itself checked.
- `src/tools/diag/sig.ts`: for a change to words only. It hashes behaviour without text, for comparing two trees.
- `src/tools/diag/ident.ts record`: the full event record of the identity seeds, one canonical JSON line per event, read through the boundary (`out-reference/`). It is what a port of the engine must reproduce line for line; any tag reproduces its own records exactly.
- `src/tools/boundarytest.ts` (in `npm test`): a world run through the boundary is identical to one run directly, and everything it gives back is plain data.
- `src/tools/mathtest.ts` (in `npm test`): the engine's own maths functions against JavaScript's, within 4×10⁻¹⁶ over the ranges the engine uses.
- `src/tools/diag/samerecord.ts`: whether two arms tell the same story, event by event (type, month, who, decision, words), and the largest gap in an option's probability.

## Known debt

- **The `tried` store** carries flags and state under text keys, and about 230 places reach past the types (`as any`) for fields the person type does not declare (`lastIll`, `interestFrom`, couple state). A typo fails silently. It moves to named, typed fields when a round touches it.
- **Circumstances in `extra`**: some situations give every option the same circumstance (short of money, already stretched), so it cannot push one way. Whether that changes behaviour is a question for a round, not a cleanup.
- **Portability** (`docs/scale/portability.md`): the `tried` store and the `as any` above (rule 5); the setting pack and the words of acts live in code (`setting.ts`, `families.ts`, `motives.ts`), not in data (rule 7).
- **The Understory page** lists source files by path; the published page needs its files republished when the layout changes.
